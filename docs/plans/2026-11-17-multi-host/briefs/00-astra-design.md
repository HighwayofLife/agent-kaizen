## What to decide
- Architecture: one source of truth with per-host manifests/adapters (generated by a stdlib script, or hand-kept) vs relying on formats the hosts already share. Where hook payloads differ: a thin adapter layer vs per-host scripts. Prefer the simplest.
- Capability matrix: each component (each skill, the agent, each hook, token-audit, templates) × each host: works as-is / needs adapter / degraded / not possible, and what the user sees when degraded.
- Repo layout changes, install docs per host, test and CI changes (per-host validation where a validator CLI exists), and how the version/changelog rule in AGENTS.md extends to new manifest files.
- Risks and unknowns; owner decisions as **Decisions needed**, each with a recommendation.
- Packet outline: ordered packets (about one brief each) with scope, files, acceptance criteria, verify commands, a risk tag (low/normal/high) and a suggested tier (Luna for short text/docs-only, Terra for code). Concrete, but don't write the briefs.
