# 09 fix round 2 (high risk): enforce append-only by verification

Worktree: agent-kaizen-wt-09 (branch kz-09: 9caf650 packet, c0337fd fix 1). Read 09-scheduled-wiring.md and 09-fix1.md. The owner has decided that New World's scheduled review **stays in `auto` mode**, so the append-only guarantee must hold even though auto mode allows some Bash commands.

The re-review found that allowed Bash commands can still write files. For example, `git log --output=<ledger.csv>` (allowed by `Bash(git log:*)`) truncates the ledger; this was reproduced. `rg --pre` can also run programs. Permission rules match prefixes and cannot reliably forbid a flag, so enforce the guarantee in the runner instead:

1. **Ledger integrity guard in `scripts/kaizen-scheduled` (review/cycle runs in auto *and* propose mode).**
   - Before launching Claude, for each configured ledger file (csv, timeline), copy it to the run's private state dir and record its size and sha256.
   - After the run, require that the file still exists, that its first `old_size` bytes hash to the recorded sha256, and that any growth is whole lines. The timeline may be legitimately rewritten by `notes-ledger add` through its atomic temp-file-and-rename insert, so for the timeline require only that every line of the old file still appears in order in the new file.
   - On any violation: restore the snapshot atomically (temp file plus rename); mark the run `ledger-violation` in its report and status, with the paths; exit non-zero; and do not apply any further steps of that run.
   - If the guard itself errors (unreadable file, etc.), fail closed: report and skip the auto-apply steps.
2. **Narrow the allow list where it is cheap.**
   - Drop `Bash(git log:*)` and `Bash(git diff:*)` if no skill step needs them; check skills/*/SKILL.md and the review prompt.
   - If they are needed, keep them and rely on the guard. Either way, document in docs/scheduling.md: "Bash commands can write files; the ledger is protected by the post-run guard, not by permission rules."
3. **`scripts/install-schedule:357`.** Before writing `bin/.kaizen-plugin-root`, refuse (exit 2) if the path is a symlink; then write atomically. `--remove` deletes the record.
4. **`kaizen-backup begin`/`finish`.** Reject `--run`/`--skill` values containing `/`, `..` or NUL, and reject a `CHANGE_DIR` that is outside the backups root after resolving. Exit 2.

**Tests.** Each must fail without its fix:
